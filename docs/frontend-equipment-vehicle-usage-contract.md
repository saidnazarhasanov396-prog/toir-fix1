## Main Business Rules

### Ordinary Equipment

For non-vehicle equipment, frontend should send the responsible person directly:

```json
{
  "category": "PRODUCTION_EQUIPMENT",
  "responsibleId": "employee-or-user-uuid"
}
```

Backend stores this in:

- `equipment.responsibleId`

Frontend should display it from:

- `response.responsibleId`

### Vehicle

For vehicles, frontend must not use a separate responsible person selector as the source of truth.

Frontend should send:

```json
{
  "category": "VEHICLE",
  "assignedDriverId": "hr-employee-uuid"
}
```

Backend stores:

- `vehicleDetails.assignedDriverId`
- `equipment.responsibleId` with the same value

Driver validation:

- driver must exist in HR employees
- driver must be active
- driver must have active work role `DRIVER`
- driver must be in the same department as the vehicle
- one driver can be assigned as default driver to only one vehicle

Recommended driver lookup:

```http
GET /api/v1/hr/employees?active=true&departmentId={departmentId}&workRoleCode=DRIVER
```

## Field Semantics

### Common Equipment Response Fields

These fields are available in `EquipmentDto`:

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | UUID | Equipment id. For vehicles this is also `equipmentId`. |
| `code` | string | Backend-generated equipment code. Do not submit from frontend. |
| `name` | string | Equipment/vehicle name. |
| `inventoryNumber` | string | Required inventory number. |
| `model` | string | Model. |
| `producedYear` | integer | Produced/manufactured year, 1900..2100. |
| `responsibleId` | UUID | Responsible person. For vehicles this equals `assignedDriverId`. |
| `category` | enum | `PRODUCTION_EQUIPMENT`, `VEHICLE`, etc. |
| `averageDailyUsage` | number | Average expected daily usage. Unit depends on `lifetimeCounterType`. |
| `expectedLifetimeHours` | number | Legacy/engine-hours max lifetime. |
| `lifetimeCounterType` | enum | Dynamic lifetime counter type. |
| `lifetimeMeterId` | UUID | Explicit meter id, if configured or resolved. |
| `lifetimeLimitValue` | number | Maximum lifetime/resource limit. |
| `lifetimeBaselineValue` | number | Starting meter value for lifetime calculation. Defaults to `0` when limit is configured. |
| `lifetimeWarningPercent` | number | Expiring-soon threshold percent. Defaults to `10` when limit is configured. |
| `lifetimeCurrentValue` | number | Current meter value. Null until active meter exists. |
| `lifetimeTargetValue` | number | `baseline + limit`. |
| `lifetimeRemainingValue` | number | `target - current`. Null until current meter exists. |
| `lifetimeConsumedPercent` | number | `(current - baseline) / limit * 100`. Null until current meter exists. |
| `lifetimeUnit` | string | Display unit: `h`, `km`, `cycle`, `t`, `kWh`, or meter custom unit. |
| `lifetimeStatus` | enum | `NORMAL`, `EXPIRING_SOON`, `EXPIRED`, `UNKNOWN`. |

### Meter Type Values

Use these enum values exactly:

```text
ENGINE_HOURS
MILEAGE_KM
CYCLES
TONS_PRODUCED
KWH_CONSUMED
CUSTOM
```

Recommended labels:

| `lifetimeCounterType` | Label | Default unit |
| --- | --- | --- |
| `ENGINE_HOURS` | Engine hours | `h` |
| `MILEAGE_KM` | Mileage | `km` |
| `CYCLES` | Cycles | `cycle` |
| `TONS_PRODUCED` | Production volume | `t` |
| `KWH_CONSUMED` | Energy consumed | `kWh` |
| `CUSTOM` | Custom | use meter unit if available |

### Average Daily Usage

`averageDailyUsage` means "how much this asset is expected to work per day".

Display unit should be derived from `lifetimeUnit` or `lifetimeCounterType`:

| Counter type | Example label |
| --- | --- |
| `MILEAGE_KM` | `250 km/day` |
| `ENGINE_HOURS` | `8 h/day` |
| `CYCLES` | `120 cycle/day` |
| `TONS_PRODUCED` | `40 t/day` |
| `KWH_CONSUMED` | `500 kWh/day` |

Validation:

- optional
- if provided, must be positive
- do not send `0`

### Maximum Lifetime / Resource

Use `lifetimeLimitValue` for the maximum amount this equipment can work from baseline.

Examples:

- Vehicle can drive max another `300000 km`: `lifetimeCounterType=MILEAGE_KM`, `lifetimeLimitValue=300000`
- Motor can work max `18000 h`: `lifetimeCounterType=ENGINE_HOURS`, `lifetimeLimitValue=18000`
- Tool can run max `10000 cycles`: `lifetimeCounterType=CYCLES`, `lifetimeLimitValue=10000`

Backend calculates:

```text
lifetimeTargetValue = lifetimeBaselineValue + lifetimeLimitValue
lifetimeRemainingValue = lifetimeTargetValue - lifetimeCurrentValue
lifetimeConsumedPercent = (lifetimeCurrentValue - lifetimeBaselineValue) / lifetimeLimitValue * 100
```

If no meter exists yet, current/remaining/consumed values may be null. The configured limit still returns.

## UI Logic Checklist

### Create/Edit Selector

If asset category is vehicle:

- Use vehicle form and `/api/v1/vehicles`.
- Show driver selector.
- Do not show separate responsible person selector, or show it read-only as "same as assigned driver".
- Submit `assignedDriverId`.
- Submit `manufactureYear`, `averageDailyUsage`, and lifetime fields as top-level vehicle request fields.

If asset category is not vehicle:

- Use equipment form and `/api/v1/equipment`.
- Show responsible person selector.
- Submit `responsibleId`.
- Submit `producedYear`, `averageDailyUsage`, and lifetime fields.

### Driver Selector

Filter HR employees by:

- active employees only
- same department as vehicle
- work role `DRIVER`

Recommended request:

```http
GET /api/v1/hr/employees?active=true&departmentId={departmentId}&workRoleCode=DRIVER
```

On department change:

- clear selected driver if driver department no longer matches
- refetch drivers for the new department

### Lifetime Input UX

Suggested field group:

- Counter type: select enum
- Maximum resource: numeric input
- Current/baseline meter value: numeric input
- Warning threshold percent: numeric input, default 10
- Average daily usage: numeric input

Recommended labels by counter type:

| Counter type | Max label | Baseline label | Average daily label |
| --- | --- | --- | --- |
| `MILEAGE_KM` | Max mileage resource, km | Start odometer, km | Average km/day |
| `ENGINE_HOURS` | Max engine hours | Start engine hours | Average h/day |
| `CYCLES` | Max cycles | Start cycles | Average cycles/day |
| `TONS_PRODUCED` | Max production, tons | Start production meter | Average tons/day |
| `KWH_CONSUMED` | Max energy, kWh | Start energy meter | Average kWh/day |
| `CUSTOM` | Max custom resource | Start custom meter | Average units/day |

### Display Rules

For configured lifetime:

```text
Target = lifetimeTargetValue
Remaining = lifetimeRemainingValue
Consumed = lifetimeConsumedPercent
Status = lifetimeStatus
```

If `lifetimeCurrentValue` is null:

- show configured maximum resource
- show target if `lifetimeTargetValue` exists
- show current/remaining as "No meter reading yet"

If `lifetimeStatus`:

- `NORMAL`: normal style
- `EXPIRING_SOON`: warning style
- `EXPIRED`: danger style
- `UNKNOWN`: neutral style

## Validation Notes For Frontend

General:

- `code` is backend-generated. Do not include it in create/update payloads.
- `averageDailyUsage` must be positive if sent.
- `lifetimeLimitValue` must be positive if sent.
- `lifetimeBaselineValue` must be zero or positive.
- `lifetimeWarningPercent` must be positive.
- `producedYear` / `manufactureYear` should be 1900..2100.

Vehicle:

- `name`, `inventoryNumber`, `equipmentTypeId`, `departmentId`, `plateNumber`, `vehicleType` are required.
- `assignedDriverId` is optional, but if sent, backend validates it strictly.
- Driver assignment may fail with:
  - `Assigned driver employee not found`
  - `Assigned driver employee is not active`
  - `Assigned employee must have DRIVER work role`
  - `Assigned driver must be in the same department as the vehicle`
  - `Assigned driver already has a default vehicle`

Equipment:

- `name`, `inventoryNumber`, `equipmentTypeId` are required.
- At least one valid location placement is required by existing equipment location logic.
- If dynamic lifetime is not supplied, expected lifetime must be positive.
